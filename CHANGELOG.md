## [Unreleased]

### Changed

- `app.py` simplified to thin HTTP adapter over `Orchestrator` — no business logic, just auth + request routing
- Restructured project from flat layout to feature-based directory structure — each submodule (`config/`, `rules/`, `delivery/`, `models/`, `analysis/`, `tr/`, `templates/`, `orchestrator/`) now has co-located `tests/`, `features/`, and `README.md`
- Renamed `signals/` to `rules/` with `builtin/` subdirectory for built-in rule implementations
- Moved `telegram/` under `delivery/channels/telegram/`
- Moved `config.py` to `config/models.py` with re-exporting `__init__.py`
- Top-level `tests/` now contains only shared fixtures and integration tests
- Replaced env-var-based `pydantic-settings` configuration with YAML config file (`pac.yaml`)
- Replaced `AssetClass` enum with dynamic string-based asset IDs defined in config
- `SignalRule` converted from `typing.Protocol` to `ABC + Generic[ParamsT]` with `__init_subclass__` auto-extraction of `params_model`
- Signal rules now receive typed params (`ThresholdParams`, `CycleInversionParams`, `PacPlanParams`) instead of raw settings
- `Signal.metadata` type widened to `dict[str, Any]`

### Added

- Added `Orchestrator` class (`src/pac/orchestrator/`) for framework-agnostic signal dispatch with `from_settings()` factory
- Added dynamic signal routing via `POST /jobs/signal/{signal_name}` — replaces hardcoded per-signal routes
- Added `dispatch_signal()`, `evaluate_signal()`, `get_portfolio_status()`, `compute_pac_plan()` on `Orchestrator`
- Added `build_template_data()` classmethod on `SignalRule` for rule-specific template context
- Added `set_orchestrator()` lifecycle hook on `DeliveryChannel` for interactive channel DI
- Added `TemplateEngine` with Jinja2 `SandboxedEnvironment` for safe, format-agnostic message rendering
- Added `FormatAdapter` ABC for channel-agnostic formatting (bold, italic, code, escape, literal, etc.)
- Added `MarkdownV2Adapter` and `PlainTextAdapter` format adapter implementations
- Added 4 builtin templates: `threshold_alert`, `cycle_alert`, `pac_plan`, `portfolio_status`
- Added `DeliveryChannel[ConfigT]` ABC for extensible delivery channels with `__init_subclass__` config auto-extraction
- Added `TelegramChannel` implementation with PTB lifecycle hooks (`start`/`stop`/`process_update`)
- Added channel auto-discovery (`discover_channels()`) scanning `pac.delivery.channels` for concrete subclasses
- Added `RenderedMessage` model for channel-agnostic message delivery
- Added `create_bot_from_app()` factory for Telegram PTB `Application` setup
- Added `just new-rule <name>` scaffolding command for signal rules
- Added `just new-channel <name>` scaffolding command for delivery channels
- Added `just validate-config` CLI for validating `pac.yaml` configuration
- Added dev dependencies: pytest-bdd, pytest-xdist, pytest-sugar, pytest-randomly, pytest-cov, pytest-timeout
- Added contributor guides: `docs/bdd.md`, `docs/testing.md`, `docs/documentation.md`
- Expanded submodule READMEs with architecture tables and usage examples
- Added Google-style docstrings on public API surfaces
- Added test coverage: PAC plan rule BDD scenarios, `build_template_data()` tests, orchestrator partial failure tests, template/config/delivery/model edge cases, TR client error wrapping
- Added `pac.yaml.example` reference configuration file
- Added config loader (`config/loader.py`) with `${ENV_VAR}` interpolation in YAML values
- Added `pyyaml` dependency
- Auto-discovery (`discover_rules()`) scans `pac.rules.builtin` for concrete `SignalRule` subclasses
- `PacPlanRule` for monthly PAC plan computation with `compute_pac_plan()` (Settings-free)

### Removed

- Removed legacy `create_bot()`, `send_signal_alert()`, `send_pac_notification()`, `evaluate_all()` — replaced by `Orchestrator` pipeline
- Removed `pydantic-settings` dependency — replaced by YAML config + pydantic models
